  2. Critical schema divergence: prod DB is dangerously under-constrained

  account table — critical

  ┌───────────────────┬─────────────────────┬──────────────────────────────────────────┐
  │      Column       │ Prod (db_from_prod) │          Local dev / create.sql          │
  ├───────────────────┼─────────────────────┼──────────────────────────────────────────┤
  │ name              │ VARCHAR(20)         │ VARCHAR(100)                             │
  ├───────────────────┼─────────────────────┼──────────────────────────────────────────┤
  │ email             │ VARCHAR(20)         │ VARCHAR(254) (RFC standard)              │
  ├───────────────────┼─────────────────────┼──────────────────────────────────────────┤
  │ password          │ VARCHAR(20)         │ VARCHAR(60)                              │
  ├───────────────────┼─────────────────────┼──────────────────────────────────────────┤
  │ profileVisibility │ No CHECK constraint │ CHECK(IN ('public','friends','private')) │
  └───────────────────┴─────────────────────┴──────────────────────────────────────────┘

  The password VARCHAR(20) on prod is catastrophic. bcrypt hashes are 60 characters long. The prod database literally cannot store real bcrypt passwords — they get silently truncated, breaking authentication for any real user.

  likes table — critical

  ┌─────────────┬──────┬────────────────────────────────┐
  │    Issue    │ Prod │           Local dev            │
  ├─────────────┼──────┼────────────────────────────────┤
  │ Primary key │ None │ PRIMARY KEY (pinID, accountID) │
  └─────────────┴──────┴────────────────────────────────┘

  Without a primary key, users can like the same pin multiple times, corrupting the like count.

  pin table

  ┌───────────────────┬──────────────────────────────┬───────────────────────────┐
  │ Column/Constraint │             Prod             │         Local dev         │
  ├───────────────────┼──────────────────────────────┼───────────────────────────┤
  │ likes             │ No DEFAULT 0                 │ DEFAULT 0                 │
  ├───────────────────┼──────────────────────────────┼───────────────────────────┤

  comment & post tables

  - Foreign keys in prod are missing ON DELETE CASCADE, so deleting a user/pin won't clean up related rows.

  post table — missing columns
